The idea

What is localization, and why?

LocalizationMaking the app fit a language and a region: words, text direction, numbers, dates
LocaleA language code + an optional country code: en, ar, ar_LY (Arabic, Libya)
LTR / RTLLeft-to-right (English) and right-to-left (Arabic): in Arabic the whole screen is mirrored
Why? People trust and use apps in their own language. In Libya many users read Arabic first. One app reaches more people.

The package

easy_localization: what it does and how to install it

What it does

  • Reads translations from JSON files in assets/
  • context.tr('key'), values inside text, plurals
  • Switches the language with context.setLocale(...) and remembers it
  • Brings flutter_localizations with it: no extra package to add

Setup · Step 3

main(): start easy_localization

lib/main.dartmain()
void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await EasyLocalization.ensureInitialized();

  runApp(
    EasyLocalization(
      supportedLocales: const [Locale('en'), Locale('ar')],
      path: 'assets/translations',
      fallbackLocale: const Locale('en'),
      child: const MyApp(),
    ),
  );
}
async / await“Wait for this to finish before going on” (it reads the saved language)

pathWhere the JSON files are
fallbackLocaleUsed when the phone's language is not supported: a French phone gets English

Without startLocale, the first launch follows the phone's language: a phone set to Arabic (Libya) opens in Arabic.

Translate

Keys and context.tr()

Flat key 
{ "login_title": "Welcome back" }

→ context.tr('login_title')

Nested key · we use this 
{ "login": { "title": "Welcome back" } }

→ context.tr('login.title') · one group per page

Showing a translation
Text(context.tr('login.title'))  // use this inside build()
'login.title'.tr()               // also works, see notes
tr('login.title')                // also works, see notes
Only context.tr() rebuilds the text when the language changes. Use the short forms only outside build(), for example a SnackBar message in onPressed.
Mobile App Development · Lecture 11

context.tr() tells Flutter “rebuild me when the language changes”. The short forms 'key'.tr() and tr('key') do not: we tested it, and a page using 'login.title'.tr() kept showing “Welcome back” after switching to Arabic. Use them only outside build(), for example in a SnackBar message inside onPressed.

Mobile App Development · Lecture 11

Arabic has a dual form (رسالتان), so ar.json has two; English does not need it. Arabic also changes the noun after 10 (“11 رسالة”), so our Arabic other is written as “عدد الرسائل الجديدة: {}”, which is correct for 3, 11 and 100. (For full Arabic rules there is ignorePluralRules: false with few and many; not needed today.)

Switch

Change the language: a LanguageButton

lib/widgets/language_button.dart
class LanguageButton extends StatelessWidget {
  const LanguageButton({super.key});

  @override
  Widget build(BuildContext context) {
    final bool isArabic = context.locale.languageCode == 'ar';

    return TextButton.icon(
      onPressed: () {
        context.setLocale(isArabic ? const Locale('en') : const Locale('ar'));
      },
      icon: const Icon(Icons.language),
      label: Text(isArabic ? 'English' : 'العربية'),
    );
  }
}
context.setLocale(...)Changes the language and rebuilds the app: no setState needed
condition ? a : bIf the condition is true use a, else b
The choice is saved on the phone automatically: close the app, open it again, still Arabic.

The label shows the other language, in its own script:

العربية in the English app
English in the Arabic app
Mobile App Development · Lecture 11

Our own custom widget again (Lecture 8), so we can put it on every page. The label shows the other language written in its own script (“العربية” / “English”), which is what most apps do. condition ? a : b means “if the condition is true use a, else b”.

Right-to-left

RTL: what flips by itself, and what does not

Arabic locale → the whole app becomes right-to-left automatically.

Flips by itself: Row, the AppBar back arrow, TextField icons, CrossAxisAlignment.start
Does not flip: anything that says left or right
start = where reading starts: left in English, right in Arabic.

The messages row in Arabic: with left: 8 the gap jumps to the outer side and the text touches the icon.

start: 8
عدد الرسائل الجديدة: 3
left: 8
عدد الرسائل الجديدة: 3

Use start / end instead:

Fixed (stays put)Directional (flips)
EdgeInsets.only(left: 8)EdgeInsetsDirectional.only(start: 8)
Alignment.centerRightAlignmentDirectional.centerEnd
TextAlign.leftTextAlign.start
lib/home_page.dartthe messages row
Padding(
  padding: const EdgeInsetsDirectional.only(start: 8),
  child: Text(context.plural('home.messages', newMessages)),
),
Mobile App Development · Lecture 11

start means “where reading starts”: left in English, right in Arabic. Live: change “Forgot password?” back to Alignment.centerRight, switch to Arabic, and it sticks to the wrong side. Change it to AlignmentDirectional.centerEnd and it follows the language. Symmetric values like EdgeInsets.all(24) are fine as they are.
